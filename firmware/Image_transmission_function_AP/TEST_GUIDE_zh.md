# Image_transmission_function_AP 测试说明

[English](TEST_GUIDE_en.md) | **简体中文**

适用：当前 AP 模式固件测试与出厂验证。本文是测试规程，不代表设备已经通过实测。测试不使用 LCD。

## 1. 测试准备

- 待测板、配套摄像头、稳定电源（5V ≥ 2A）及数据线。
- 支持 Wi-Fi 的电脑或手机（当前 `sdkconfig.defaults` 默认启用 **2.4 GHz 信道 1**；若需验证 **5 GHz / Wi-Fi 6** 协商，请先在 `idf.py menuconfig -> Example Configuration -> Wi-Fi AP band` 切换为 5 GHz 后再使用支持 5 GHz / Wi-Fi 6 的终端测试）。
- 完整、清晰、无反光的 tag36h11 标签，提前记录其 ID。
- 白纸或浅色背景、带文字和彩色区域的实物，用于人工画质检查。
- 外部 I2C 主机，使用 3.3 V 逻辑电平，建议总线速率 100 kHz。

连接或调整接线前断电，I2C 主机与待测板共地。不得将 5 V 逻辑信号直接接入 GPIO。

| 功能 | 当前配置 |
| --- | --- |
| BOOT 测试按键 | GPIO35，低电平有效 |
| 外部 I2C SCL / SDA | GPIO47 / GPIO46 |
| 外部 I2C | I2C1 从机，7 位地址 `0x54` |
| 摄像头 I2C SCL / SDA | GPIO29 / GPIO28，与外部 I2C 独立 |
| C5 SDIO 复位 | GPIO50，高电平有效，延时 700 ms |

外部 I2C 的 SCL、SDA 需有合适的 3.3 V 上拉，不能只依赖内部弱上拉。

## 2. 烧录与连接

开发环境下执行，`COMx` 替换为实际串口：

```bash
source /path/to/firmware/export.sh   # ESP-IDF v6.1
cd firmware/Image_transmission_function_AP
idf.py set-target esp32p4
idf.py build
idf.py -p COMx flash monitor
```

1. 上电后连接热点 `ESP32-P4C5-CAM-XXXXXX`，后缀为设备 MAC 的后三字节，以串口实际输出为准。当前热点无密码。
2. 默认配置（`sdkconfig.defaults`）使用 **2.4 GHz 信道 1** 以兼容各类终端；若通过 `idf.py menuconfig` 切换为 5 GHz，则启用 Wi-Fi 6 并在 36/40/44/48 信道中选择。客户端实际使用的协议需在客户端查看。
3. 保持连接该热点，即使终端提示“无互联网”。浏览器访问 `http://192.168.5.1`。
4. 页面标题应为 `ESP32P4C5-Mini`，上电默认显示“图传模式”。视频使用端口 81。

测试时建议只连接一个观看视频的终端，并关闭其他视频页面，减少带宽和连接干扰。

## 3. 图传与摄像头画面检查

在“图传模式”下完成以下检查：

1. 确认画面连续更新，移动镜头前物体，观察是否存在长时间冻结、花屏或断流。
2. 确认显示完整画面，不是中心裁剪图。当前传感器配置为 800×600。
3. 在均匀光线下对准白纸或浅色背景，查看是否有固定污点、黑点、暗角或亮度不均。移动背景，检查异常是否始终固定在画面相同位置。
4. 对准文字和彩色实物，检查是否清晰，有无明显偏色、条纹或画面异常。
5. 下载 JPEG，确认能够打开且尺寸正确；下载原始图像，确认文件非空。当前 800×600 RGB565 原始文件预期为 960000 字节，不含文件头，需要按该格式查看。
6. 在网页设置中调整 JPEG 质量并保存，确认视频可恢复显示；恢复原质量设置。

通过标准：视频、下载、设置功能正常，画面无明显污点、偏色、模糊或其他异常。画质由人工确认；AprilTag 识别成功不能代替画质检查。发现异常需保留 JPEG 和现象说明。

## 4. BOOT 按键与模式切换

1. 在“图传模式”下短按 GPIO35 对应的 BOOT 按键，网页应切为“测试模式”。
2. 松开后再按一次，应恢复“图传模式”。
3. 长按一次，不应持续来回切换；松开后再次按下才能触发下一次切换。
4. 重复短按切换，确认无漏触发或一次按下重复切换现象。

通过标准：按键可可靠切换模式。

## 5. AprilTag 识别测试

1. 保持网页视频打开，短按 BOOT 进入“测试模式”。本模式持续识别，不是此前的单帧或 2 秒窗口模式。
2. 将 tag36h11 标签完整放入画面，保留周围空白，调整距离与光线，使标签足够大且清晰。
3. 观察网页是否显示包围标签的检测框，ID 是否与测试标签一致。
4. 缓慢移动标签，观察检测框和 ID 更新。移走标签后，检测框应在后续空检测或结果过期时消失。
5. 再按 BOOT 切回“图传模式”，确认检测框消失，视频继续播放。

通过标准：能够识别到预期标签 ID，检测框位置基本正确，切换前后图传正常。

## 6. 外部 I2C 通信测试

本项测试使用 GPIO47/46，不是摄像头 GPIO29/28。

1. 断电后连接主机 SCL → GPIO47、SDA → GPIO46、GND → GND，再上电。
2. 浏览器访问 `http://192.168.5.1/api/tests`，检查 `i2c` 状态。正常初始化、尚未收到正确数据时为 `0`。
3. 主机向 **7 位地址 `0x54`** 发起一次原始写事务，写入以下 14 字节 ASCII：

```text
ESP32P4C5-MINI
45 53 50 33 32 50 34 43 35 2D 4D 49 4E 49
```

不得添加寄存器地址、NUL、回车、换行，也不要拆分为多次事务。

Linux I2C 主机示例（`BUS` 替换为实际总线编号）：

```bash
i2ctransfer -y BUS w14@0x54 0x45 0x53 0x50 0x33 0x32 0x50 0x34 0x43 0x35 0x2d 0x4d 0x49 0x4e 0x49
```

4. 刷新 `/api/tests`，`i2c` 应变为 `1`，即通信测试通过。

## 7. 结果读取与判定

主网页仅显示模式、视频及识别框，不显示完整测试状态表。通过浏览器访问 `/api/tests` 获取结果：

| 字段 | 含义 |
| --- | --- |
| `camera` | 至少识别到一个标签后为 `1`，不代表人工画质检查通过 |
| `boot` | 检测到一次有效按下后为 `1` |
| `i2c` | 收到规定的完整字符串后为 `1` |
| `all_passed` | 上述三项均为 `1` 时为 `true`，不包含人工画质结论 |

状态值：`0` 等待测试；`1` 通过；`2` 引脚未配置；`3` 初始化失败。通过状态保持至重启，刷新网页或切换模式不会清除。

## 8. 建议稳定性检查与故障排查

| 现象 | 优先检查 |
| --- | --- |
| 搜不到热点 | 终端是否支持 5 GHz；设备供电；C5/SDIO 启动日志 |
| 网页能开但没视频 | 端口 81 是否可访问；是否打开多个视频页面；相机初始化日志 |
| 按键没有切换 | 是否为 GPIO35 对应按键；按下是否接地；是否已松开上一次按键 |
| 标签无框 | 当前是否为测试模式；是否为 tag36h11；标签大小、距离、光照 |
| I2C 不通过 | 47/46 接线、共地、上拉、7 位地址、14 字节内容及事务边界 |
| `i2c=3` | 查看 `External I2C init: ...` 错误日志，排查引脚冲突或驱动失败 |
| `mempool_alloc failed` 或持续卡顿 | 减少视频客户端，检查网络和供电，保留完整日志 |
| `task_wdt` 或异常重启 | 判为待排查，保留错误前后串口日志，不以重启后恢复作为通过 |
